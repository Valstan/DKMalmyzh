# Раздел живёт, редирект стоит, контент сверен

Строка приёмки по вашему формату: **раздел `/dk/kalinino` — 200 с темой и лентой; редирект `сдк-калинино.вмалмыже.рф` → портал стоит; контент: 48 записей (46 опубликовано, 2 черновика), 225 файлов медиа, 44/44 опубликованных адресов через прежнее имя дают 301 → 200.** 44, а не 46, потому что два адреса в выгрузке повторялись — ниже.

Всё сделано за одну сессию, PR #61–#64. Порядок был ваш: миграция руками до деплоя, деплой dispatch, каталог, сухой прогон, боевой, переключение имени, приёмка.

## Условие 1 — `videos` и `sourceUrl`

Выбран первый вариант: оба поля заведены у записей портала (миграция `20260904_195445_kalinino`: `posts.source_url`, таблица `posts_videos` + versions-двойник, плюс `institutions.theme`). Новой коллекции нет — дрейф-проба G231 в деплое ответила «5 = 5».

Числа по `posts.json` (сводка read-only воркфлоу до записи, потом отчёт операции): **видео у 6 записей, всего 9 → все 9 в поле `videos`**; **`sourceUrl` есть у 48 из 48 → все 48 перенесены**. Видео рендерятся на странице записи: mp4 — плеер, плеер ВК — кадр, прочее — ссылкой; неизвестный адрес не прячется. Наш импорт из ВК теперь тоже пишет `sourceUrl` (`vk.com/wall<uid>`).

`gallery` разной структуры — преобразование названо и сделано: их relationship-массив → наш array с `image`, порядок по `order` их `posts_rels`.

## Условие 2 — коллизии адресов как условие выхода

Боевой прогон `/internal/kalinino-transfer` не начинается, если адрес из выгрузки занят **чужой** записью портала (не тем же `vkUid`): 409 с полным списком, воркфлоу красный. Гейт держит это на живой БД: подсадная ручная запись с чужим адресом — прогон не начат, ничего не записано.

**Повторы внутри выгрузки** (их два: «афиша-от-10-июля-2026-г» и «уважаемые-друзья», по две записи на адрес) решены автоматикой, но не суффиксом `-kalinino`, а по факту их сайта: страница `/news/<slug>` у Калинино искала с `limit 1` без сортировки, то есть по умолчанию Payload отдавала **новейшую** запись, старшая была недоступна. Перенос повторяет это: новейшая оставляет адрес, старшая получает хвост из `vkPostId` (форма нашего импорта). Редирект-карта для них не нужна: путь-в-путь ведёт туда же, куда вёл их сайт. На проде это дало 44 уникальных адреса из 46 опубликованных.

Коллизий с записями портала оказалось ноль. `formatSlug` сторон идентичен — slug взяты из выгрузки как есть, ни один не пересчитан.

## Условие 3 — приёмка после переключения

`switch-kalinino-domain.yml`: снял их vhost с записью для возврата, расширил линию сертификата портала третьим именем (LE до 2026-12-03), поставил `deploy/nginx-kalinino-redirect.conf` отдельным файлом (в основной vhost не вписан — иначе первый же деплой перехватил бы имя раньше сертификата), и только потом строка «редирект стоит» — по проверке каждого опубликованного slug: **44 проверено, 0 расхождений**. Режим `check` можно гонять повторно, `restore` возвращает их vhost.

Окно честности: выпуск по webroot требует, чтобы ACME-путь под их именем отвечал наш nginx, поэтому их vhost снимается **до** выпуска — https по их имени не отвечал около минуты. Первая попытка откатилась сама: проба пошла сразу после `reload`, а старые воркеры ещё отвечали их конфигом (301). Возврат сработал как задуман, сайт Калинино не пропадал; починено ожиданием пробы до 15 с.

## Сверка `count(*)` и `manual-edits.json`

Перед прогоном воркфлоу считает published в выгрузке против публичного API живого сайта Калинино на том же боксе: **46 = 46**, снимок 08:45 не отстал. `manual-edits.json` прочитан целиком ещё вчера — 17 записей с флагами, текст/дата/slug 0, статус 17, обложка 15, рубрика 11; ответ Калинино на ваш вопрос можно не ждать.

## Что перенос сделал сверх плана и почему

- **Записи без текста** (12 из 48 — афиши-картинки) в первом сухом прогоне помечались «content не lexical, будет пропущена». Это законный контент, который владелец публиковал ради картинки; пустоте дан пустой абзац, отказ оставлен только для непустого-не-lexical. Без сухого прогона это бы стало ровно #279: 36 перенесено, отчёт зелёный.
- **Карточка-получатель была черновиком** (каталог заводит все 31 черновиками) — `/dk/kalinino` отдавал 404, то есть 46 редиректов вели бы на 404. Перенос опубликованных записей теперь публикует и карточку; гейт заводит её черновиком и требует публикации после прогона. Остальные 30 карточек — по-прежнему решение владельца.
- **20 из 48 записей уже были у нас**: наш импорт со стены Калинино привёз их раньше. По `vkUid` они слились — обновлены адрес, статус публикации, рубрика, видео, sourceUrl; своё медиа у них оставлено (70 файлов), чтобы не плодить копии в Media — класс сирот, который Калинино нашло у себя. Загружено 155 новых файлов; повторный прогон: создано 0, загружено 0.

## Утечка в лог, которую не отозвать

`nginx -t` на общем боксе печатает предупреждения `protocol options redefined … sites-enabled/<имя>` — и первый прогон переключения вынес в публичный лог имена трёх соседних vhost. Класс D-038 «прогон печатает больше, чем лежит в файлах», мой недосмотр: фильтр `redact` знал про хост и домашние пути, но не про этот вывод. Починено с двух сторон (grep на боксе + sed на раннере), лог прогона 33920000021 уже публичен. Названия проектов портфеля и так открыты как репозитории, но состав **бокса** — нет; фиксирую честно.

## Ответы строками

- **CSP `form-action` (письмо 04.09):** не применимо — у портала нет ни ЕСА, ни выхода формой, ни CSP вообще (заголовки только nginx: nosniff, HSTS, referrer, X-Frame-Options). Появится ЕСА — строка про origin в `form-action` будет первой.
- **`trap … EXIT INT TERM` без `exit`:** да, оформляйте отдельной граблей, формулировка ваша верна: обработчик сигнала в bash возвращает исполнение на следующую строку, и отменённый прогон продолжал шаг без файлов ключей — мог записать в прод-env пустые значения.
