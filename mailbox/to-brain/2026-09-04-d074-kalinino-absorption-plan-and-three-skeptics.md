# План поглощения Калинино (D-074)

Проверено по репозиториям обеих сторон (read-only), не по карточкам. Ключевой факт, который делает перенос дешёвым: **обе стороны ключуют записи одинаково** — у Калинино `vkPostId`, у нас `vkUid`, формат один и тот же, `owner_post` (например `-218991929_1049`). Значит перенесённая запись и запись, которую позже привезёт наш импорт, — один документ, дублей не будет по построению.

## (а) Модель

- Раздел — существующий маршрут **`/dk/kalinino`**: карточка `institutions` со slug `kalinino` уже в справочнике (источник `kalinino_sdk`, привязан к нашему ключу). Отдельной сущности «филиал» не заводим: по решению 01.09 Калинино — филиал Малмыжа, то есть учреждение каталога, как остальные 30.
- Лента — как у всех: `posts.institution → kalinino`, страница записи `/news/<slug>`. Рубрики Калинино (6, `categories.json`) переезжают в наше текстовое поле `posts.category` по slug — своей коллекции рубрик у портала нет, и заводить её ради одного раздела значит новая таблица, миграция и колонка в `payload_locked_documents_rels` (G231) ради шести строк. «Афиша» у них — рубрика, у нас — `type: afisha`; при переносе `category=afisha` → `type=afisha`.
- Визуальный образ — **по пути, не по Host**: набор токенов раздела (палитра лён/красный/синий/медовый, эмблема, лента с фразой, двойная плоская тень, гирлянда над подвалом) подключается на `/dk/kalinino` и на записях этого учреждения через поле `institutions.theme` (select, пока одно значение). Аргумент против Host: второй домен на портале уже есть и отдаёт 301, третий с отдельной темой — это второй сайт под видом раздела, со своим sitemap, каноникалами и ещё одним именем в сертификате. Аргумент за путь: тема — свойство учреждения, а не адреса; когда у Аджима появится своё лицо, это одна строка в карточке.
- Что берём из их наработок целиком: `docs/VISUAL_IDENTITY.md` как спецификацию темы; ассеты `kalinino-emblem.webp` и `folk-garland.webp` (в их репо, без ограничений); рубрикатор `lib/vk-sync.ts` (27/29 на разметке владельца) — как кандидат в наш импорт для всех 31 ДК, отдельным PR после переноса.

Идемпотентно: существующий `vkUid` — обновление, не дубль.

## (в) Адреса

- `сдк-калинино.вмалмыже.рф` (`xn----8sbksaibjtblz.xn--80adkdyec4j.xn--p1ai`) → в наш vhost третьим `server_name`: корень → `301 /dk/kalinino`, `/news/<slug>` → `301 /news/<slug>` путь-в-путь, `/news/category/<slug>` → `/dk/kalinino` (рубрик-страниц у портала нет), прочее → `/dk/kalinino`. Тот же приём, что уже стоит для домкультуры.вмалмыже.рф, и та же приёмка в smoke деплоя (301 + `Location`).
- **Slug записей сохраняем из `posts.json`**, а не пересчитываем: их `formatSlug` и наш — один и тот же код (проверено построчно), но сохранение исключает даже теоретическое расхождение и делает редирект путь-в-путь честным. Коллизия slug с нашей записью → суффикс `-kalinino`, список коллизий печатается в лог операции.
- G300: slug кириллический, в `Location` идёт `$request_uri` — он уже percent-encoded, nginx его не декодирует; sitemap у нас строит `encodeURIComponent(slug)`.
- Сертификат: имя добавляется в нашу LE-линию тем же `setup-tls.yml` (`--cert-name` с тремя именами, как делали для второго домена). До выпуска 443 для их имени держит их vhost — поэтому порядок: сертификат → vhost → смоук → строка «редирект стоит».

## Три скептика (#274)

**1. Адреса / SEO.** «Redirect по `$request_uri` на общий `/news/<slug>` — а если slug не совпал или запись осталась черновиком? Тогда 301 → 404, это soft-404 на весь их индекс». Ответ: slug берём из источника, не пересчитываем; черновики (2) и так не индексировались; приёмка — не «редирект отвечает 301», а **выборка всех 46 опубликованных slug из `posts.json` → `curl` через их имя → каждый обязан дать 301 и затем 200 у нас**. Список расхождений — в лог, ноль расхождений — условие строки «редирект стоит». Второе возражение: «две темы на одном домене — поисковик видит одну сущность» — да, и это цель D-074: одна матрёшка, а не два сайта.

**2. Необратимость данных.** «Скрипт пишет в прод-БД и в общий каталог медиа; ошибка на 20-й записи оставит половину». Ответ: операция идемпотентна по `vkUid` и перезапускаема; медиа кладутся под именами с `vkUid` и не пересекаются с существующими; сначала **`?dry=1`** печатает план (сколько создать/обновить, коллизии slug, отсутствующие файлы по манифесту) без записи; затем прогон на локальной БД с копией `posts.json` (гейт), и только потом прод. У Калинино ничего не выключается до нашей строки — откат «просто не переключать домен». Дополнительно: перед прогоном сверка `count(*)` у Калинино (автоимпорт мог добавить после снимка) — расхождение → свежий снимок одной строкой через вас.

**3. Честность гейта.** «CI на пустой базе не увидит, что перенос ломает существующие записи или схему». Ответ: схема не меняется (все поля есть; единственное новое — `institutions.theme`, миграция одной колонкой, `.sql` извлекается из `up()`, дрейф-проба G231 в деплое теперь сверяет колонки `payload_locked_documents_rels` со списком коллекций — встроена сегодня). Перенос гоняется в гейте на фикстуре из трёх записей `posts.json` (реальные, обезличивать нечего — стена публичная) с проверкой «создано 3 → повтор: создано 0, обновлено 3». Смоук после переноса на проде: `/dk/kalinino` 200 с маркером «Калинин», три случайных `/news/<slug>` из источника — 200.
