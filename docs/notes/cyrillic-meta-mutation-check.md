# Мутационная приёмка регрессионной защиты (проверено 2026-10-02)

## Зачем

Новый e2e-тест `новость с кириллическим адресом имеет свои метаданные и canonical`
обязан КРАСНЕТЬ без фикса `postMeta`. Проверять защиту «зелёным прогоном с
фиксом» бессмысленно: тест, который ничего не ловит, тоже зелёный.

## Как проверялось

Локальной БД и Docker на машине нет — e2e без Postgres не гоняется. Поэтому
проверка выполнена **мутацией на одноразовой ветке**: в `postMeta` возвращён
поиск по НЕдекодированному slug (ровно то, как было до фикса), ветка ушла в CI
на красный прогон и не мержится. Правило приёмки — из `AGENTS.md` §Гейты
(«Приёмка гейта — только мутационная»).

## Результат

| прогон | ветка | ожидание | факт |
|---|---|---|---|
| мутация | `test/cyrillic-meta-mutation-red` (PR #121, закрыт без мержа) | `gates` красный на новом e2e | ✅ **красный**: 1 failed, 19 passed |
| фикс | `feat/news-description-fix` (PR #120) | `gates` зелёный | ✅ зелёный, 20 passed |

Падение мутационного прогона (цитата из лога):

```
✘  13 › новость с кириллическим адресом имеет свои метаданные и canonical
  Error: expect(page).toHaveTitle(expected) failed
  Expected pattern: /CI: новость с кириллическим адресом/
  unexpected value "Культура Малмыжского района"
```

`unexpected value` — это портальный заголовок из layout: ровно то, что видели
784 из 835 страниц на проде. Значит, защита ловит целевой класс, а не что-то
попутное. Ветка удалена, PR закрыт без мержа, счётчики не затронуты.

## Что именно ловит тест

Три утверждения, каждое падало по отдельности при снятом декодировании:
1. `toHaveTitle` — без фикса приходил портальный заголовок из layout;
2. `meta[name=description]` содержит текст записи — без фикса приходило общее описание;
3. `link[rel=canonical]` не null и указывает на саму страницу — без фикса тега не было ВООБЩЕ.

Третье — самое ценное: отсутствие тега, а не неверное значение. Проверка вида
«нет тега → считаем главной» зеленела бы именно в этом случае.
