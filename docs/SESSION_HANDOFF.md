## Грабли и находки этой сессии

- **`grep -i` не матчит кириллицу** в Git Bash под Windows (локаль C): `grep -ni 'калинино'` — пусто, `grep -n 'Калинино'` — находит. На этом первая перепроверка recon-аудита отрапортовала ложно-чисто. Проверки по русскому тексту писать с явными вариантами регистра: `grep -nE '[Гг]оньба|[Кк]алинино'`. Родственник — G259 (`\w` в JS не включает кириллицу). Опасны одинаково: обе **молчат**, и проверка выглядит пройденной.
- **`nginx -T` печатает конфиги вместе с комментариями.** Диагностика искала слово `default_server` и поймала наш же комментарий про соседа — отчиталась «держим мы» при том, что держит сосед. Матчить надо директиву: `^[[:space:]]*listen[^#]*default_server`. Поймано только прогоном по настоящему выводу.
- **Снапшот, снятый задним числом, описывает текущий конфиг, а не состояние миграции.** С `push: true` в dev конфиг уезжает молча. Критерий законности — `diff` сгенерированной полной схемы против исходной миграции; не совпало — класть нельзя.
- **«`payload migrate` в CI зависает из-за drizzle push prompt» — неверный диагноз.** Зависал **push**, а не CI: с `PAYLOAD_DB_PUSH=false` CLI отрабатывает штатно, `migrate:status` отдаёт таблицу и выходит. Заметка стояла в `deploy-prod.yml` и README миграций с июня и была верна как наблюдение, но из неё следовал ложный вывод — что payload CLI в CI недоступен в принципе.
- **`.gitleaks.toml` нужен свой:** дефолтные 195 правил ВК-токен не видят вовсе, Telegram в URL пропускают. Подсадной для приёмки брать **случайный** — пример из документации вендора лежит в дефолтном allowlist и оставляет гейт зелёным (G258).
- **`paths-ignore` деплоя не покрывает корень репозитория.** `.gitleaks.toml` в корне триггерит `deploy-prod`, хотя `**.md` и `.github/**` — нет.
- Прежние грабли живы: бокс делят несколько сайтов (нужен контент-маркер «РЦКД», не код 200); TLS терминирует сам nginx; ACME-webroot в `/var/www`; nginx 1.24 → `http2` как параметр `listen`; информер Метрики отстаёт от кабинета на часы.

## Как устроен гейт миграций (не сломать при правках)

`PAYLOAD_DB_PUSH=false` в job `gates` → схему даёт миграция, а не автосинхро. Накат — `psql -f` по всем `src/migrations/*.sql`, **тем же путём, каким миграция едет на прод**; гейт по `.ts` через `payload migrate` проверял бы артефакт, которого на проде нет.

⚠️ **Сид `web/scripts/seed-ci.ts` обязан обновлять существующий документ, а не только создавать.** Проверено мутацией 31.08: при миграции без колонки `posts_id` создание страницы и новости прошло, легло обновление. Сид без шага обновления оставляет гейт зелёным на сломанной схеме — это сигнатура G231 у Калинино, где весь импорт был созданием и дыра прожила 18 дней.

На проде `push` остался включённым: `PAYLOAD_DB_PUSH` там не задан, дефолт прежний. Build-БД деплоя одноразовая, прод-схему по-прежнему даёт ручная миграция через `apply-migration.yml`.
