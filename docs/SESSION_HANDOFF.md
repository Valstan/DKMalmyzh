## Аудит вечера 04.09 (#51, #52) — четыре зелёные проверки, не проверявшие ничего

Многоагентный аудит собственных изменений дня. Каждая находка перечитана по коду, все починены и уехали на прод.

- **Дрейф-проба G231 стояла внутри `Migration guard` с `if: event_name != workflow_dispatch`** — то есть выключалась ровно на том пути, которым миграции и приезжают на прод. Вынесена отдельным шагом без условия; список коллекций берётся из массива `collections` в `payload.config.ts`, а не globом по каталогу; неразобранный slug роняет шаг. Первый живой прогон: «колонок 5 = коллекций 5, чисто».
- **Замок импорта имел гонку:** проверка до `await getPayload`, установка после — два запроса проходили оба, то есть вчерашнее лекарство от аварии её не предотвращало. Замок вынесен в `web/src/lib/internal/lock.ts`, берётся синхронно, общий с `seed-institutions`. Мутация: старая схема пускает 3 из 3 параллельных вызовов, новая — 1.
- **`alternates: { canonical: '/' }` в корневом layout** проставлял канониклом главную КАЖДОЙ странице при живом sitemap — разделы выпадали бы из индекса. Канонический адрес задаётся постранично через `canonicalOf`; проверено на проде.
- **`inputs.slug` интерполировался в тело `run:`** — кавычка в значении выполняла бы произвольную команду в шаге с приватным деплой-ключом. Теперь через `env` и с валидацией.
- Попутно: `trap` без `exit` на INT/TERM мог записать в прод-env пустые ключи; файлы с ключом оставались в `/tmp` бокса; тело ответа шлюза и длина с sha256-префиксом ключей печатались в публичный лог; `curl --fail` в юните глушил тело (409 и 503 выглядели одинаково) — запуск идёт через `deploy/dkmalmyzh-vk-sync-run.sh`; `Persistent=true` снят.

⚠️ **Сам аудит с первого раза не состоялся:** девять агентов подряд упали на сетевых и авторизационных ошибках API, вернув пустой результат. Пустой результат такого прогона означает «не проверено», а не «чисто».

## Второй аудит: данные (#56–#59)

Измерения по живым данным дали ещё восемь находок, две с потерей.

- **Импорт стирал источники ВК из карточки.** `runVkSync` перезаписывал `institutions.vkSources` массивом только тех источников, которые удалось разрезолвить в этот прогон. Флаг «что-то изменилось» общий на учреждение, поэтому ссылка, поймавшая 429 или переименование, исчезала, как только сосед по массиву обновил свой `ownerId`. У головного РЦКД пара «короткое имя + числовой адрес» — числовой всегда проходит, короткое имя ходит в шлюз. Теперь обходится исходный список, меняется только кэш.
- **123 записи под 49 одинаковыми адресами.** Slug считался из заголовка, а заголовки импорта повторяются по построению. Поле не `unique`, страница отдаёт первый попавшийся документ — при публикации порядка 74 материалов были бы недоступны при живых ссылках из ленты. Slug теперь несёт `vkUid`; существующие записи переименованы операцией `/internal/reslug-vk`. **Проверено пробой: дублей 0 из 636.**
- Дедлайны у обращений наружу (шлюз 30 с, фото 20 с), вырезание серверных путей из сообщений об ошибках, черновики без ревалидации, правила редактирования в пробе по форме (IPv4, баннер Next, проза psql).

### Три грабли, каждая сама выглядела как успех

1. **Проба не могла покраснеть.** `ssh … | redact` под дефолтной оболочкой `bash -e` без `pipefail`: кодом шага становился код `sed`. Приёмка выгрузки Калинино держалась на проверке, которая физически не могла провалиться. Лечится `shell: bash`.
2. **Правка ушла в версию, а не в запись.** `payload.update` с `draft: true` пишет в `_posts_v`, а `posts.slug` остаётся прежним. Операция отрапортовала «переименовано 636, с ошибкой 0», проба показала те же 49 дублей. Симметрично: `payload.find` с `draft: true` читает версии — второй прогон ответил «без изменений 636», глядя на уже исправленные версии при старой основной записи. Теперь операция и пишет, и читает основную запись, а после каждого обновления перечитывает документ и сверяет адрес.
3. **`ssh` не передаёт argv.** Он склеивает аргументы в строку, удалённый шелл разбирает её заново: пустой аргумент исчезает, следующие сдвигаются. Запуск с пустым `slug` и `dry_run=true` отдал «true» в slug — «сухой» прогон оказался боевым и честно написал `dryRun: false`. Значения передаются именованными переменными.

## Грабли и находки этой сессии

- **`gh pr merge --auto` в репо выключен** (`enablePullRequestAutoMerge`) — мерж руками по зелёному.
- **`.github/**` в `paths-ignore` деплоя:** правка workflow не выкатывается сама, нужен `gh workflow run deploy-prod.yml --ref main`; при dispatch Migration guard пропускается.
- **Сеть до GitHub мигает** (TLS handshake timeout) — команды `gh` оборачивать в повтор. У соседей то же самое, их обход — SOCKS-туннель через бокс (`ssh -N -D 1080`, `https_proxy=socks5h://…`).
- **Адрес соседнего сайта берём у самого соседа, а не из письма.** В письме Мозга по D-075 назван прежний домен Сабантуя; их деплой проверяет, что он отдаёт 301 на `сабантуй.вмалмыже.рф`. Ссылка через редирект живёт до непродления регистрации — прецедент дкмалмыж.рф.
- **Многоагентный аудит 04.09 с первого раза не состоялся:** девять агентов подряд упали на сетевых и авторизационных ошибках API. Пустой результат такого прогона означает «не проверено», а не «чисто» — перезапускать, а не засчитывать. Со второго раза прошёл и дал четыре блокера.
- **Канал этой машины фильтрует избирательно.** `1.1.1.1` и GitHub API отвечают за доли секунды, наш прод — TLS-рукопожатие 12,5 с при мгновенном TTFB после него, `example.com` и сайты праздников не соединяются вовсе (пинг проходит, TCP нет). Медленность прода, замеренная отсюда, — свойство канала, а не сервера: проверять изнутри бокса. Обход у соседей — SOCKS-туннель через бокс.
- Прежние грабли живы: бокс делят несколько сайтов (маркер «Малмыж»); TLS терминирует nginx; кириллица в `grep -i` не матчится; heredoc в Bash-инструменте съедает `\`+перенос.
